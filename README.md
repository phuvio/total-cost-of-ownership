# Total Cost of Ownership Estimator

A framework and interactive calculator for estimating the Total Cost of Ownership (TCO) of
Large Language Model (LLM) applications.

This project is developed as part of a master's thesis at the University of Helsinki on
cost-aware selection and deployment of Large Language Models in production environments.

The interactive estimator is at
[https://phuvio.github.io/total-cost-of-ownership/](https://phuvio.github.io/total-cost-of-ownership/).

## Replication material

**`scripts/` regenerates the results reported in the paper** *"Self-Hosting or API?
Undisclosed Parameters and the Engineering-Effort Boundary in LLM Deployment Architecture."*
Two commands rebuild the result tables and every figure from the case parameters, with no
network access and no configuration:

```python
python scripts/run_all.py        # the result tables  -> out/
python scripts/make_figures.py   # Figures 1-4        -> figures/
```

Together they take a few seconds. `run_all.py` chains the seven analysis steps in order, so
there is nothing to run by hand and no step can be run out of sequence. The outputs are
deterministic: re-running reproduces the deposited tables value for value.

Python 3.10 or later. `run_all.py` and the seven step scripts it calls use **only the Python
standard library** — nothing to install. `make_figures.py` additionally needs numpy, pandas
and matplotlib (`requirements.txt`).

| Directory | Contents |
| --- | --- |
| `scripts/` | the analysis pipeline: `tco_model.py` (the cost model), seven step scripts, `run_all.py`, `make_figures.py` |
| `data/` | inputs — the case parameters, the published parameter tables, and the reference model's extracted figures |
| `out/` | the nine result tables regenerated by `run_all.py` |
| `figures/` | the paper's Figures 1–4, regenerated by `make_figures.py` |
| `appraisal/` | the grey-literature appraisal: protocol, per-source scores, search record |

One exception to the above: `derived_shares.csv` holds the acquisition- and recurring-share
figures and is **not** regenerated by the pipeline — it is shipped as a derived summary and
is the one table in the deposit that `run_all.py` does not write.

[`README-replication.md`](README-replication.md) maps each claim in the paper to the file and
the script that produce it; start there if you arrived from the paper.

## Purpose

Deploying LLM-based applications involves more than API token pricing. Real-world costs may
include inference, training and fine-tuning, GPU and infrastructure, retrieval and vector
databases, guardrails and moderation, engineering and implementation effort, and the effect
of optimization techniques such as caching, routing, batching and quantization.

The project provides a practical framework for comparing deployment strategies, estimating
training-versus-inference trade-offs, identifying crossover points where inference cost
dominates, and evaluating how optimization decisions affect total lifecycle cost.

## Features

The calculator implements:

- an interactive TCO calculator with cost breakdown and a training-versus-inference
  crossover visualization;
- three deployment modes — API-based, cloud-hosted and self-hosted;
- optimization modeling for caching, model routing, quantization, prompt compression,
  batching and speculative decoding;
- adjustable assumptions and scenario analysis.

**What the paper evaluates is narrower than what the calculator implements.** The paper's
cross-validation exercises the API and self-hosted modes with every optimization term set
to zero, which is the parameterization its Section IV describes and Section III.E bounds.
The optimization factors above are extension points in the model, not terms this study
validated. Treat the calculator's optimization outputs as illustrative.

## Research context

The framework is informed by scientific literature on LLM inference and deployment, by
industry documentation and technical reports, and by a grey-literature review appraised
with the AACODS criteria: **96 sources appraised, 41 core, 23 supporting, 32 excluded.** The
protocol, the per-source scores and the search record are in `appraisal/`, including
the excluded sources and their scores, so the exclusion decisions are checkable.

## Monthly TCO from the terminal

`scripts/tco-monthly.ts` evaluates cumulative TCO month by month over 24 months, using the same 30.44-day month as the cost model. It calls `calculateTCO` from `src/lib/tco-calculations.ts` directly, so it is the way to exercise the TypeScript implementation — the authoritative one — from the command line.

Provide a JSON file containing any model fields to override; omitted fields use the calculator defaults:

```powershell
npm run tco:monthly -- --file model.json
```

Example `model.json`:

```json
{
  "modelType": "api",
  "inputTokenPrice": 2.175,
  "outputTokenPrice": 13.05,
  "requestsPerDay": 10000
}
```

The command writes a CSV of 24 rows — one per month — with columns `month`, `cumulativeHardwareSetupCost`, `cumulativeInferenceCost`, `cumulativeEngineeringOperationalCost`, `cumulativeEnergyCost` and `cumulativeTCO`. It prints the row count, the monthly electricity cost and the month-24 TCO to the terminal. Model JSON can also be passed as an argument or piped through standard input. `--output` defaults to `scripts/tco-monthly.csv`; pass `out/` as above to keep generated data out of the code directory.

## Agent endpoint

The repository includes an optional AI setup agent that suggests parameter values in the
user interface, served at `/api/agent`.

- In development, Vite serves the endpoint through local middleware.
- In production, deploy to Vercel or another serverless host that serves `api/agent.ts`.
- Set `ANTHROPIC_API_KEY` in the serverless environment to enable model-backed responses.
- Without the key, the handler falls back to deterministic local suggestions.

**The agent is a user-interface convenience and plays no part in the cost model.** No result
in the paper or the thesis depends on it, and the analysis pipeline does not call it.

## Status

The **web application** is a prototype under active development, intended for
experimentation, visualization and research rather than production-grade financial
estimation.

The **replication material** is frozen at the state that produced the paper's results. The
pipeline regenerates the nine result tables and the four figures from
`data/case_parameters.csv` in one pass — every output except the shipped `derived_shares.csv`
noted above — so the deposited outputs and the paper are one run.
